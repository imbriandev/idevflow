# Define

Read existing project evidence first. State user, problem, promise, smallest complete path, non-goals, and one falsifiable TestFlight learning question. Mark unsupported claims as assumptions; never invent research.

Use write preflight to create the configured product-memory and SLC documents. Include first-run, empty, loading, failure, accessibility, privacy, and trust expectations only when they affect the primary path. Present unresolved high-risk assumptions for founder acceptance, then verify docs, postflight, finish, and integrate.

Do not write production code or change release settings. Stop for changes to user, promise, or monetization. Use `idev_context` only for relevant product, interface, accessibility, or paid-value ambiguity.
