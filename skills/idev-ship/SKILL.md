# Ship

Use fresh release verification for the exact reviewed commit. Validate required privacy, release, monetization, screenshot, accessibility, and performance evidence. Create the candidate, present blockers and known issues, and request interactive approval before promotion.

Create the handoff after promotion. Never imply that iDevFlow pushed, signed, uploaded, selected testers, or distributed. Use `idev_context` for the critical release surfaces only.
