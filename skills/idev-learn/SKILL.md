# Learn

Read feedback and the prior learning question. Preserve useful user language; separate repeated evidence from requests and assumptions. Decide now, later, not-do, or investigate against the product promise, then select one next focus.

Update product memory through preflight, docs verification, postflight, finish, and integration. Do not turn every request into scope or change the user, promise, or monetization without founder approval. Use `idev_context` only when the feedback requires a relevant specialist lens.
